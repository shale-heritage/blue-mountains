● You're absolutely right to question this! Looking at the accommodation report and the AAT guidance, I see the issue
  now:

  Getty AAT Approach

  AAT uses:
  - <guide terms in angle brackets> - organizational only, NOT taggable
  - churches (buildings) - the plural IS taggable as a descriptor
  - cathedral, basilica, etc. - specific types also taggable

  So AAT allows tagging with BOTH the general plural term AND specific instances.

  But I Think We Decided Differently

  Looking at your accommodation report, I see many items tagged with Hotels (plural), but these seem incorrect based on
   your recollection.

  For example, Item #4:
  "Mr. Lindeman purposes erecting a handsome building at Leura as an hotel..."

  This was tagged with Hotels but should probably be:
  - ✗ Hotels (plural category - organizational, not for tagging)
  - ✓ Hotel (singular generic - an unnamed hotel)

  Correct pattern should be:
  Hotels ← ORGANIZATIONAL ONLY, not for tagging
  ├─ Hotel ← TAG THIS when "a hotel" mentioned but not named
  ├─ Carrington Hotel ← TAG THIS when specific hotel named
  └─ Megalong Hotel ← TAG THIS when specific hotel named

  Question for You

  Should I revise the accommodation report to:
  1. Remove all instances of Hotels (plural) tags
  2. Replace with Hotel (singular) when the article discusses unnamed/generic hotels
  3. Only use specific hotel names when those hotels are identified

  This would align with the principle of only tagging with leaf nodes (actual descriptors), not with
  organizational/category terms.

  Is that what you decided?

> Yes, I think that we should follow (more or less) the AAT strategy and not use intermediate levels for tagging but 
instead include a 'generic' taggable term at the bottom of each heirarchy (only tagging with leaf nodes). Please remove
 all instances of Hotels (plural) and replace with Hotel (singular) and only use specific hotel names when those hotels
 are identified. Can you generalise this leaf node only rule and start a 'tagging guidelines' document that (a) we can 
refer to when questions come up and (b) you can later use for automated tagging? 

● Excellent! This is a critical clarification that will prevent confusion going forward. Let me:

  1. Create a comprehensive tagging guidelines document
  2. Fix the accommodation report to use only leaf nodes

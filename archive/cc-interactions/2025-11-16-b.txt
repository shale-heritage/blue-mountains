● Based on my investigation, here's where dates appear in your project:

  Date Usage Contexts

  1. Item metadata (CSV files) - ISO format YYYY-MM-DD
  - entity-tagging-system/outputs/*/item_tag_application.csv files
  - Example: 1893-06-02, 1889-06-29, 1896-02-07
  - Purpose: Zotero item dates (publication dates from newspaper articles)
  - Current format: ISO (YYYY-MM-DD)

  2. Taxonomy notes field - Written-out format
  - Single example found: pre-March 1892 in notes for "Fryer's Family Hotel"
  - Purpose: Historical context in notes/explanations
  - Rare usage, appears as prose

  3. Script generation timestamps - ISO format with time
  - Backup files: tag_map_consolidated.20231116_143052.bak
  - Report metadata: datetime.now().isoformat()
  - Current format: ISO (YYYY-MM-DD HH:MM:SS)

  4. STYLE_GUIDE.md section 4.1 - Your proposed "Day Month Year" format
  - Examples given: 2 June 1893, 15 October 1889
  - Currently documented but NOT USED anywhere in actual data

  Recommendation

  Keep ISO format (YYYY-MM-DD) for all machine-readable contexts:
  - ✅ Item metadata CSVs (already ISO)
  - ✅ Script timestamps and backups (already ISO)
  - ✅ Report generation timestamps (already ISO)

  Use Day Month Year for human-readable prose ONLY:
  - Taxonomy notes field when writing historical context
  - Documentation/planning files
  - Markdown reports

  Rationale:
  1. ISO is already used throughout your data files and scripts
  2. Sortability - ISO sorts correctly as strings (critical for CSVs,
  filenames)
  3. Interoperability - Zotero, databases, scripts expect ISO
  4. No ambiguity - 2025-06-03 is unambiguous (vs 3 June 2025 or 3/6/2025)

  Proposed STYLE_GUIDE.md revision:

  ### 4.1 Date Formatting

  **Rule:** Context-dependent formatting

  **Machine-readable contexts (CSV files, metadata, timestamps):**
  - Use ISO format: `YYYY-MM-DD`
  - Examples: `1893-06-02`, `2025-11-16`
  - Rationale: Sortable, unambiguous, interoperable

  **Human-readable prose (notes field, documentation):**
  - Use Day Month Year: no leading zeros, no commas
  - Examples: `2 June 1893`, `15 October 1889`
  - NOT: `June 2, 1893` (US format) or `02 June 1893` (leading zero)

  **Filenames:**
  - Always ISO: `backup_20251116.csv`, `report_2025-11-16.md`

  Would you like me to update STYLE_GUIDE.md section 4.1 with this
  context-dependent approach?
